# 케이스 저장

`metaxtract-storage`는 Rust의 단일 SQLite 파일 케이스 저장소를 담당합니다.
스캐너의 재개용 작업 저널과 분리되어 있어 케이스를 여는 데 네이티브 파서를
불러올 필요가 없습니다. 새 케이스는 기존 파일을 덮어쓰지 않고 원자적으로
생성하며, 트랜잭션에 내구성 있는 롤백 저널과 외래 키를 사용합니다.

`CaseWorkspace::open(path, AccessMode::ReadOnly)`는 마이그레이션이나 복구
쓰기를 수행하지 않습니다. 쓰기 모드에서는 지원하는 이전 Rust 스키마를
하나의 트랜잭션으로 이관하며, 알 수 없는 이후 스키마는 거부합니다.
Python 케이스는 원본을 유지한 채 새 Rust 케이스로 가져옵니다.

## 메타데이터 기록

`begin_scan`으로 스캔을 시작하고 `append_record` 또는 원자적인
`append_records`로 `ExtractionRecord`를 저장한 뒤 `finish_scan`으로 마칩니다.
타입이 유지되는 원본 기록과 검색용 관측값·해석값·충돌·진단을 함께 저장하고,
읽을 때 SHA-256을 검증합니다. 원본 바이트, 미확인 태그, 부동소수점 비트,
출처와 128비트 시각을 스키마 표현 그대로 유지합니다. 증거 경로는 대소문자를
구분하며 중첩 컨테이너의 식별 정보도 보존합니다. 기록 하나의 직렬화 한도는
256 MiB이며, 초과하면 메타데이터를 자르지 않고 트랜잭션 전체를 취소합니다.

## 페이지 조회

`RecordQuery`는 상태, MIME, 대소문자를 구분하는 경로 접두사, 정규화 키·값,
충돌 여부와 부호 없는 64비트 크기 범위로 스캔을 조회합니다. 페이지에는
메타데이터 본문 대신 목록 정보만 담으며, 삽입 순서·경로·크기 순서의 키셋
커서를 사용합니다. 한 페이지는 256개 행과 16 MiB로 제한합니다. 커서는
케이스·변경 차수·조회 조건에 연결되므로 케이스가 바뀌면 처음부터 조회합니다.
전체 기록은 `record(id)`로 명시적으로 읽습니다.

## 이력과 케이스 작업

`scan_history`는 스캔 출처·상태·시각·진단 수를 페이지로 읽습니다. 일시 정지한
스캔은 명시적으로 재개하며, 케이스를 열었다는 이유로 다른 스캐너의 작업을
실패로 바꾸지 않습니다. 케이스 노트, 작성자별 개별 노트, 제한된 태그가 있는
기록 주석과 이름 있는 필터는 트랜잭션으로 저장합니다. 구조화 필터는
`RecordQuery`를 유지하고 Python 필터는 원래 질의문과 상태를 별도로 보존합니다.

## 가져오기

`import_jsonl`은 Python 스캔 행과 Rust 추출 기록을 읽습니다.
`import_python_case`는 스키마 1~3의 Python 케이스를 일관된 SQLite 사본으로
읽으며 원본을 이관하거나 수정하지 않습니다. 스캔 이력·노트·주석·필터를
유지하고 원래 행과 케이스 정보도 가져오기 기록에 보존합니다. 기존 관측값에
네이티브 출처나 정규화 결과를 새로 만들어 붙이지 않습니다.

`import_python_bundle`은 모든 멤버의 경로·CRC·확장 한도, 목록의 크기·SHA-256,
스캔 개수와 해시 목록을 검사합니다. 서명된 번들은 명시적으로 신뢰하는
Ed25519 공개 PEM 키가 필요하며, 공개키를 지정하면 무서명 번들도 거부합니다.
포함된 원본 증거 파일을 검증하되, 메타데이터를 가져올 때 실제 원본 파일은
원래 번들에 유지합니다. 정확한 매니페스트·서명·신뢰 키 정보는 케이스에 남깁니다.

`ImportLimits`로 입력 크기, 멤버 크기·개수, 확장된 총 크기, 기록 크기·개수와
제어 파일을 제한합니다. 실패하면 일부 기록만 남기지 않고 전체를 되돌립니다.
`append_records_with_receipt`는 스캐너의 원래 경로·파일 식별·해시·실패 정보를
직렬화해 추출 기록과 원자적으로 함께 저장할 때도 사용할 수 있습니다.
