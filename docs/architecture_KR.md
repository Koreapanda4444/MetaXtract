# MetaXtract 아키텍처

[English](architecture.md) | [한국어](architecture_KR.md) | [프로젝트 README](../README_KR.md)

## 제품 범위

MetaXtract는 메타데이터 추출·분석 프로그램입니다. 바이너리 파싱은 메타데이터를 찾고,
디코딩하고, 검증하고, 설명하기 위해 사용합니다. 범용 헥스 편집기, 디스어셈블러, 디버거,
임의의 바이너리 분석 도구를 만드는 것은 제품 범위에 포함하지 않습니다.

## 역할 분담

Rust는 영구 저장 상태와 사용자에게 보이는 정책을 담당합니다.

- GUI와 CLI의 동작
- 파일 탐색, 식별, 해싱과 무결성 검증
- 작업 스케줄링, 취소, 캐시 키, 체크포인트와 자원 정책
- 공통 스키마, 정규화, 교차 분석과 이상 탐지
- 케이스 저장, 검색, 비교, 개인정보 제거, 보고서와 이동 가능한 번들

C++는 메모리 안전성을 별도로 검증해야 하는 네이티브 추출 코어를 담당합니다.

- 메타데이터에 접근하는 데 필요한 바이너리 구조 파싱
- 메타데이터 값이나 미리보기를 해석하는 데 필요한 디코딩
- 원본 메타데이터를 손실 없이 추출
- 허용된 네이티브 라이브러리를 감싸는 어댑터

C++는 충돌하는 값 중 어느 것이 맞는지 결정하거나, 케이스 파일을 저장하거나,
사용자 디렉터리를 탐색하거나, 네트워크에 접근하거나, 앱의 사용 흐름을 구현하지 않습니다.

## 의존 방향

GUI와 CLI는 Rust 코어를 사용하고, Rust 코어는 공통 스키마와 Rust/C++ 연결부에 의존합니다.
연결부가 C++ 추출 어댑터를 호출합니다.

C++ 코어는 GUI, CLI, 저장소, 보고서 또는 케이스 관리 코드를 호출하지 않습니다.
파서 라이브러리는 어댑터 내부에 숨기며 해당 라이브러리의 객체는 언어 경계를 넘기지 않습니다.

## 추출 흐름

다음은 최종 앱의 처리 흐름입니다. 스키마, 연결부, 제한된 입력 읽기와 파서 실행부는 구현되어
있지만 실제 형식 어댑터와 Rust 앱의 사용 흐름은 아직 구현 전입니다.

1. Rust가 스캔 대상을 확인하고 자원 제한이 적용된 읽기 전용 입력을 엽니다.
2. Rust가 파일 식별 정보를 기록하고 증거 처리 정책에 따라 콘텐츠 해시를 계산합니다.
3. C++가 호환되는 파서를 확인하고 서로 독립적인 원본 관측값을 반환합니다.
4. Rust가 제한 조건을 검증하고 관측값을 공통 증거 데이터로 변환합니다.
5. Rust가 해석값을 정규화하고 서로 다른 결과를 보존하면서 분석합니다.
6. Rust가 원본 파일을 변경하지 않고 결과를 저장하고 표시합니다.

연결부는 값과 진단 정보를 전달하며 C++ 객체 구조 전체를 직렬화해서 넘기지 않습니다.
각 결과는 사용한 파서, 알 수 있는 경우 원본의 바이트 영역, 디코딩 상태를 기록합니다.
C++ 예외는 C++ 쪽에서 잡아 구조화된 실패 정보로 변환합니다.

## 실행 시 의존성

허용된 라이브러리는 앱에 연결하거나 함께 배포할 수 있습니다. 실행 중에 ExifTool, ffprobe
또는 사용자가 별도 설치한 메타데이터 실행 프로그램을 호출해서는 안 됩니다.
빌드 도구는 앱 실행 시 의존성과 구분합니다.

## Python 기준판

동결된 Python 앱은 기존 사용 흐름을 비교하기 위한 실행 가능한 기준판입니다.
Python이 추출한 적 없는 필드의 정답까지 결정하지는 않습니다. Rust와 C++가 호환성 검증,
케이스 데이터 호환성, 전체 사용 흐름의 검증을 통과한 뒤 Python을 대체합니다.

[`architecture.toml`](../architecture.toml)은 저장소 검증에서 사용하는 역할 분담 설정입니다.
관련 구현 제약은 [언어 경계](ffi_KR.md), [의존성 정책](dependencies_KR.md),
[자원 제한](resource-limits_KR.md)을 참고합니다.
