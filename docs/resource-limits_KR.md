# 파서 자원 제한

[English](resource-limits.md) | [한국어](resource-limits_KR.md) | [프로젝트 README](../README_KR.md)

각 네이티브 파서는 독립적인 `ParserBudget`을 받습니다. 어댑터는 큰 입력을 읽거나,
메모리를 할당하거나, 디코딩 결과를 만들거나, 컨테이너 내부로 들어가거나, 항목을 열거하거나,
관측값을 출력하기 전에 사용할 자원을 예산에 반영해야 합니다.
긴 반복문 안에서는 `checkpoint`를 호출해 시간 제한을 협력적으로 확인해야 합니다.

`run_parser`는 실행 문맥을 만들고, 어댑터 호출 전에 지나치게 큰 입력을 거부하며,
어댑터 예외를 처리합니다. 어댑터가 자원 제한 실패를 무시하고 성공을 반환하더라도
최종 예산 상태를 검사합니다. 읽기는 `ParserContext`를 거치며 읽은 바이트와 Rust 콜백·C++
결과에 쓰는 두 버퍼를 자동으로 계산합니다. Rust는 파서마다 독립적인 읽기 세션을 제공하므로
여러 파서가 반복 또는 동시에 실행되어도 다른 파서의 읽기 예산을 소비하지 않습니다.

할당 제한은 계산에 반영한 메모리 할당의 누적 합계에 대한 보수적인 제한이며,
프로세스의 최대 실제 메모리 사용량을 측정한 값은 아닙니다. 외부 라이브러리 내부 할당은
어댑터별 계산이나 메모리 할당 함수에 대한 별도 처리로 반영해야 합니다.
시간 제한은 협력적으로 적용하며 어댑터 호출 전후에 확인합니다. 실행 중인 네이티브
라이브러리 호출을 강제로 중단하지는 못합니다. 향후 스캐너의 프로세스 격리로 강제 중단
경계를 마련할 예정입니다.

현재 `ParserLimits`의 기본값은 다음과 같습니다.

| 자원 | 기본 상한 |
|---|---:|
| 입력 파일 크기 | 1 GiB |
| 파서별 읽은 바이트 | 64 MiB |
| 파서별 계산된 메모리 할당 | 256 MiB |
| 파서별 디코딩 결과 | 128 MiB |
| 컨테이너 깊이 | 16 |
| 컨테이너 항목 수 | 10,000 |
| 관측값 수 | 250,000 |
| 파서별 실행 시간 | 30,000 ms |

Rust 입력 콜백은 한 번에 읽는 크기도 1 MiB로 제한합니다.
이 값들은 파일 형식의 유효성 기준이 아니라 자원 보호를 위한 상한이며,
추후 스캔 정책에서 설정할 수 있도록 제공할 예정입니다.

상한을 넘으면 원인을 구분할 수 있는 복구 가능한 오류를 반환합니다.
첫 이미지 어댑터와 추출 결과 전달부는 실패 전에 출력한 관측값을 보존합니다.
검증 전용 샘플 파서는 동일한 실행부를 통해 모든 자원 제한과
예외 경계를 검사합니다.

[언어 경계](ffi_KR.md)와 [전환 검증 안내](../conformance/README_KR.md)도 참고합니다.
