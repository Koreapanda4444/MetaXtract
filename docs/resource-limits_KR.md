# 파서 자원 제한

[English](resource-limits.md) | [한국어](resource-limits_KR.md) | [프로젝트 README](../README_KR.md)

각 네이티브 파서는 독립적인 `ParserBudget`을 받습니다. 어댑터는 큰 입력을 읽거나,
메모리를 할당하거나, 디코딩 결과를 만들거나, 컨테이너 내부로 들어가거나, 항목을 열거하거나,
관측값을 출력하기 전에 사용할 자원을 예산에 반영해야 합니다.
긴 반복문 안에서는 `checkpoint`를 호출해 시간 제한을 협력적으로 확인해야 합니다.

`run_parser`는 실행 문맥을 만들고, 어댑터 호출 전에 지나치게 큰 입력을 거부하며,
어댑터 예외를 처리합니다. 어댑터가 자원 제한 실패를 무시하고 성공을 반환하더라도
최종 예산 상태를 검사합니다. 읽기는 `ParserContext`를 거치며 읽은 바이트와 Rust 콜백·C++
결과에 쓰는 두 버퍼를 자동으로 계산합니다. Rust는 파서마다 독립적인 읽기 세션을 제공하므로
여러 파서가 반복 또는 동시에 실행되어도 다른 파서의 읽기 예산을 소비하지 않습니다.

할당 제한은 계산에 반영한 메모리 할당의 누적 합계에 대한 보수적인 제한이며,
프로세스의 최대 실제 메모리 사용량을 측정한 값은 아닙니다. 외부 라이브러리 내부 할당은
어댑터별 계산이나 메모리 할당 함수에 대한 별도 처리로 반영해야 합니다.
시간 제한은 협력적으로 적용하며 어댑터 호출 전후에 확인합니다. 실행 중인 네이티브
라이브러리 호출을 강제로 중단하지는 못합니다. 함께 제공하는 전용 파서 프로세스가
별도의 강제 중단 경계를 제공합니다.

현재 `ParserLimits`의 기본값은 다음과 같습니다.

| 자원 | 기본 상한 |
|---|---:|
| 입력 파일 크기 | 1 GiB |
| 파서별 읽은 바이트 | 64 MiB |
| 파서별 계산된 메모리 할당 | 256 MiB |
| 파서별 디코딩 결과 | 128 MiB |
| 컨테이너 깊이 | 16 |
| 컨테이너 항목 수 | 10,000 |
| 관측값 수 | 250,000 |
| 파서별 실행 시간 | 30,000 ms |
| 중첩 항목·선택한 스트림 크기 | 64 MiB |
| 원본 대비 디코딩 확장 비율 | 1,000배 |

Rust 입력 콜백은 한 번에 읽는 크기도 1 MiB로 제한합니다.
이 값들은 파일 형식의 유효성 기준이 아니라 자원 보호를 위한 상한입니다.
Rust 호출자는 정책을 조정할 수 있고 CLI는 아래의 네 가지 확장 한도를 제공합니다.

상한을 넘으면 원인을 구분할 수 있는 복구 가능한 오류를 반환합니다.
첫 이미지 어댑터와 추출 결과 전달부는 실패 전에 출력한 관측값을 보존합니다.
검증 전용 샘플 파서는 동일한 실행부를 통해 모든 자원 제한과
예외 경계를 검사합니다.

압축 한도는 자식 데이터를 할당하거나 대기열에 넣기 전, 디코딩 중에도 적용합니다.
ZIP의 선언 크기와 희소 영역을 실제 데이터로 만들기 전에 확인하며 겹치거나 뒤로 가는
블록은 거부합니다. 고정한 libarchive에는 일반 읽기와 건너뛰기의 압축 필터 출력에 모두
검사를 적용하므로 압축된 헤더와 특수 항목도 한도를 소비합니다. 각 필터 단계와 실제
항목의 출력에 디코딩 작업량을 각각 반영합니다. C 라이브러리에 들어가기 전에 계산한
64 KiB의 여유분으로 일반 할당 한도에 도달한 뒤에도 오류를 기록할 수 있습니다.

Rust는 모든 파서와 하위 항목에서 이미 사용한 읽기·할당·디코딩 양을 차감합니다.
확장 비율도 최초 루트의 크기를 기준으로 전체 트리에 적용하여 중첩마다 초기화되지 않습니다.
바이트 연산은 곱셈·복사 전에 오버플로를 검사하거나 상한에서 포화시킵니다. 한도에 걸리면
앞서 추출한 관측값을 남기고 부분 결과로 표시합니다. 남은 부분이 안전하거나 비어 있다는
뜻은 아닙니다. 정책 필드 추가로 네이티브 API 리비전은 2입니다. 이전에 저장한 정책은
새 필드의 기본값을 사용하며 기존 케이스 레코드도 계속 읽을 수 있습니다.

`scan`과 `inspect`는 `--max-member-bytes`, `--max-decoded-bytes`, `--max-tree-bytes`,
`--max-expansion-ratio`를 받습니다. 비율을 `0`으로 설정하면 비율 한도만 해제하며 바이트·시간·
전용 프로세스 메모리 한도는 유지합니다. 예를 들어
`metaxtract inspect evidence.zip --max-expansion-ratio 2000`은 다른 기본 한도를 유지하면서
확장 비율을 늘립니다. 데스크톱은 현재 기본 정책을 사용합니다.

[언어 경계](ffi_KR.md)와 [전환 검증 안내](../conformance/README_KR.md)도 참고합니다.

## 스캐너 정책

기본값은 최대 4개 작업 스레드, 8개 항목의 대기열, 16개 파일의 비용 비교 창과 재사용하는
1 MiB 해싱 버퍼입니다. 해싱과 루트 파싱은 원본 파일당 최대 1 GiB를 받으며 가상 입력은
항목당 64 MiB, 스캔 트리당 256 MiB 한도를 별도로 유지합니다. 파일 제한 시간은
120초이며 전체 스캔 제한 시간은 선택 사항입니다. 일시정지·취소와 일반 파일 입출력은
협력적으로 중단합니다.

4 GiB의 계획된 메모리 예산에서 보수적인 예약량에 따라 작업을 허용합니다. 보관하는
결과는 256 MiB, 전송·SQLite 데이터는 1 GiB 한도입니다. 예약량과 결과 크기 추정값은
전체 RSS 측정값이 아닙니다. 전용 프로세스는 Linux 주소 공간 또는 Windows Job Object의
프로세스 메모리 한도를 추가 적용합니다. macOS의 큰 예약 메모리 영역은 데이터 세그먼트
제한과 충돌하므로 Rust 부모 프로세스가 네이티브 API로 물리 메모리 사용량을 측정합니다.
macOS에서는 약 10ms마다 확인하므로 잠깐 한도를 초과할 수 있습니다. ASan 빌드는 여러
테라바이트의 가상 섀도를 예약하므로 `hard_rss_limit_mb`로 런타임의 물리 메모리 감시를
설정합니다. 일반 Linux 빌드는 주소 공간의 강제 제한을 유지합니다.
[AddressSanitizer 메모리 설명](https://clang.llvm.org/docs/AddressSanitizer.html#limitations)을 참고하세요.
`METAXTRACT_SANITIZERS=address,undefined` 빌드에서는 worker 실행 파일의 링크 의존성에
ASan과 UBSan을 직접 선언합니다. 네이티브 라이브러리 빌드 스크립트의
[Cargo 링크 인자](https://doc.rust-lang.org/cargo/reference/build-scripts.html#rustc-link-arg)는
의존 실행 파일에 전달되지 않습니다. ASan을 libc보다 먼저 연결해야 worker가 검사 기능을
활성화한 상태로 시작할 수 있습니다.

전용 프로세스에는 원본을 읽은 해시와 일치하는 사본을 전달하며 원본 쓰기 핸들은 전달하지
않습니다. 요청은 별도의 전용 제어 파일로 전달하고 stderr는 실행 중 오류 출력에 사용합니다.
부모 프로세스는 stderr를 계속 읽되 실패한 작업에 첨부할 진단은 최대 16 KiB만 보관하므로
오류 출력이 메모리에 끝없이 쌓이지 않습니다.
본체는 시간 초과·취소·충돌·잘못된 출력을 처리하고 불완전한 결과를 완료된 캐시에
넣지 않습니다. 충돌과 자원 격리이며 운영체제의 보안 샌드박스는 아닙니다. 사본 작성과 검증을
위한 추가 디스크 입출력은 정확성을 위해 유지합니다.

완료 결과는 최대 16개 또는 보관 크기 추정값 약 16 MiB까지 묶습니다. 25 ms 동안 입력이
없으면 즉시 저장해 메모리 예약이 묶음 완성을 기다리는 상황을 방지합니다. 결과 체크섬과
완료 표식을 한 트랜잭션으로 기록한 뒤 사용자 측 처리 함수에 전달합니다.
