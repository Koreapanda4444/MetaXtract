# 네이티브 추출 지원 범위

[English](extraction.md) | [한국어](extraction_KR.md) | [프로젝트 README](../README_KR.md)

## 콘텐츠 식별

Rust의 `metaxtract_native::detect_content` API는 자원 제한이 적용된 읽기 전용 입력을 통해
C++ 시그니처 판별기를 호출합니다. 최대 앞부분 64 KiB를 읽고 인식한 후보를 모두 반환합니다.
각 후보에는 MIME, 컨테이너, 근거가 있는 바이트 영역과 판별 상태가 포함됩니다.

| 상태 | 의미 |
|---|---|
| Signature | 식별 바이트를 인식했지만 구조의 유효성은 확인하지 않음 |
| HeaderValidated | 명시한 헤더 검사를 통과함. 전체 파일의 유효성을 뜻하지 않음 |
| Truncated | 인식한 헤더 또는 선언된 영역이 실제 입력 범위를 초과함 |
| Invalid | 시그니처는 있지만 헤더 필드가 서로 모순됨 |

JPEG, PNG, TIFF·BigTIFF·CR2, WebP, GIF, BMP, ICO·CUR, HEIF·HEIC·AVIF, RIFF 오디오·영상,
AIFF, FLAC, Ogg, ID3·MPEG 오디오, APE, WavPack, ISO BMFF·QuickTime, EBML,
MPEG 프로그램·전송 스트림, PDF, ZIP, OLE 시그니처를 인식합니다. ZIP 패키지의 세부 형식,
Ogg 코덱, EBML DocType과 개별 메타데이터는 더 깊은 파서가 필요합니다.
ID3 헤더만으로 뒤에 있는 데이터가 MP3 오디오임을 확정하지 않습니다.

인식되는 시그니처가 없으면 빈 후보 목록을 반환합니다. 읽기 실패나 자원 제한 초과는
알 수 없는 파일로 성공 처리하지 않고 오류로 반환합니다. 파일 시작점 밖의 시그니처와
여러 후보를 함께 보존하며 임의로 하나만 정답으로 선택하지 않습니다.

자원 예산은 [파서 자원 제한](resource-limits_KR.md), 정상·잘린·모순된·시그니처가 섞인 입력의
검증은 [전환 검증](../conformance/README_KR.md)을 참고합니다.

## 형식 충돌

Rust의 `metaxtract_core::assess_content`는 판별 후보를 확장자, 선언된 MIME,
선언된 컨테이너와 비교합니다. 원래 후보를 유지하면서 불일치, 여러 시그니처,
잘리거나 모순된 헤더, 인식하지 못한 콘텐츠와 미확인 세부 형식을 보고합니다.
대소문자와 흔히 쓰는 MIME 별칭을 정규화합니다. ZIP 파일의 DOCX 확장자나 EBML 파일의
WebM 확장자만으로 세부 형식을 확정하지 않으며 깊은 파서가 확인할 때까지 미확인으로 남깁니다.
ID3도 뒤에 있는 오디오 형식을 확정하지 않습니다. 범용 바이너리 MIME은 불필요한 충돌을 만들지 않습니다.

## 이미지 구조

네이티브 `images.structure` 파서는 JPEG 프레임·스캔·세그먼트, CRC와 순서를 검사한
PNG 청크, 일반 TIFF·BigTIFF 디렉터리, WebP 헤더·애니메이션 영역, GIF 프레임·제어 블록,
BMP DIB와 ICO·CUR 디렉터리·내장 이미지를 추출합니다. TIFF는 모르는 태그와 원본 값도
보존합니다. 항목 위치와 내장 이미지 범위는 자신을 포함하는 원본 영역 안에 있어야 하며,
디렉터리 순환 참조는 거부합니다.

`metaxtract_native::extract_parser`는 자료형을 구분한 값, 원본 바이트, 바이트 영역,
자원 사용 통계와 선택적인 실패 정보를 반환합니다. 복구 가능한 실패 전에 읽은 관측값은
계속 확인할 수 있습니다. 공통 스키마로 변환할 때 원본 바이트와 해석값을 따로 보존합니다.
구조·메타데이터 검사이며 압축된 픽셀을 디코딩해 이미지 전체의 유효성을 보증하지는 않습니다.

## 이미지 메타데이터

`images.metadata`는 EXIF·GPS·상호 운용·SubIFD 하위 디렉터리, TIFF 부호 있는 수와
실수, 알 수 없는 원본 태그, JPEG 댓글·JFIF 썸네일·Photoshop 리소스, IPTC 데이터셋,
네임스페이스를 구분한 XMP 필드, ICC 헤더와 태그를 추출합니다. 여러 JPEG ICC 조각은
순서를 복원하고 누락·중복을 검사합니다. PNG는 EXIF·일반/압축/다국어 텍스트·XMP·
압축 ICC·물리 크기·수정 시각, WebP는 EXIF·XMP·ICC·애니메이션 정보, GIF는 댓글과
애플리케이션 블록을 지원합니다. 원본 XML·프로필·데이터셋과 미해석 데이터도 보존합니다.

Pugixml은 사용자 정의·외부 엔티티를 확장하지 않습니다. Zlib은 작은 블록 단위로
압축 메타데이터를 풀면서 할당·디코딩 바이트 예산을 적용하고, XML 탐색은 깊이·항목 수·
시간 제한을 적용합니다. 해석된 필드는 원본 패킷 식별자를 가지며 파일 위치를 임의로
붙이지 않습니다. 직접 읽은 필드는 실제 원본 바이트와 위치를 유지합니다. JPEG 확장
XMP 조각은 원문과 조립 미지원 상태를 보존합니다. 픽셀과 임의의 Photoshop 리소스는
이 파서에서 디코딩하지 않습니다.

## HEIF와 카메라 RAW

`images.heif`는 HEIF·HEIC·AVIF 항목 정보, 데이터 영역, 기본 항목과 속성 연결,
크기·색·변환 속성, 항목 간 참조를 탐색합니다. 파일 영역 또는 `idat` 안의 EXIF·XMP를
추출하며, 연속 데이터는 원본 위치를 유지하고 여러 조각은 소속 항목을 식별합니다.
보호·외부 참조·미지원 조립 방식은 외부 데이터를 가져오지 않고 상태를 기록합니다.
코덱 설정은 속성 원문으로 보존하며 픽셀을 디코딩해 유효성을 보증하지 않습니다.
`images.metadata`는 Nikon 2형 메이커 노트의 TIFF 디렉터리를 해석하면서 원문도 보존합니다.

`images.raw`는 LibRaw 0.22.2를 동적 라이브러리로 포함합니다. Rust가 소유하는 읽기
전용 스트림을 통해 DNG·CR2/CR3·NEF·ARW·RAF·ORF·RW2 등 지원 카메라 RAW를 분석하고,
카메라·렌즈·일련번호·노출·센서·GPS·썸네일·제조사 해석값과 위치가 있는 원본 콜백
태그를 반환합니다. 라이브러리가 정리한 이름과 원본 태그는 다를 수 있으며 따로 보존합니다.
라이브러리 기본값은 해당 태그의 존재를 증명하지 않습니다. RAW 픽셀 풀기나 파일 직접
열기를 요청하지 않습니다.

LibRaw에는 읽기·진행 콜백의 예산, RAW 메모리 16 MiB 설정과 사전 작업 메모리 예산을
적용합니다. 라이브러리 내부의 모든 할당을 정확히 계량하거나 실행을 강제 중단하는 제한은
아닙니다. 격리된 스캔 작업자는 이후 구현하며, 예산 초과와 라이브러리 오류는 이미 추출한
값과 함께 반환합니다.

## 이미지 정보 조정

Rust의 `metaxtract_core::reconcile_image_metadata`는 원본 관측값을 수정하지 않고
출처와 연결된 공통 분석값을 만듭니다. 본 이미지·센서·썸네일·프레임·페이지·아이콘 변형의
크기를 구분하고, HEIF 기본 항목의 변환을 EXIF 방향으로 조합하며, 색 채널의 호환성을
검사합니다. 모순되는 대안은 미해결 충돌로 남깁니다. 연결 관계가 확인되지 않은 HEIF
메타데이터를 기본 이미지에 임의로 붙이지 않습니다. 본 이미지의 크기와 명시된 방향에
충돌이 없을 때 표시 크기를 계산합니다.

EXIF·ISO 시각은 날짜를 검증하고 시간대·소수 초 태그도 출처에 포함합니다. 로컬 시간대를
가정하지 않고 `-00:00`도 미상으로 유지하며, 윤초는 일반 Unix 초로 바꾸지 않습니다.
정밀도 차이만으로 시각 충돌이라고 판단하지 않습니다. 같은 파서 계열의 여러 기능은
독립적인 교차 검증으로 계산하지 않습니다. 중복 관측 ID와 여러 원본을 섞은 입력은
거부합니다. 관측 수·필드별 대안 수·분석 연결 수의 한도는 설정할 수 있으며, 초과하면
원본을 조용히 잘라내지 않고 오류를 반환합니다. 전체 케이스·레코드 동등성은 아직 검증 전입니다.

## 오디오 메타데이터

`audio.metadata`는 Rust가 소유하는 읽기 전용 스트림에서 원본 위치가 있는 C++ 구조
정보와 TagLib 2.3.2 해석값을 함께 반환합니다. MP3 ID3v1·v2와 모르는 프레임, FLAC
STREAMINFO·메타데이터 블록, Vorbis·Opus 헤더·댓글, WAV·AIFF 청크, BWF 출처·시각,
APEv2 항목과 APE·WavPack 기술 정보를 추출합니다. 반복된 태그를 보존하고 UTF-8·
Latin-1·인코딩 미상 텍스트를 구분합니다. 압축·비동기화된 ID3는 원본 패킷도 남깁니다.
TagLib이 지원하는 M4A·MP4·ASF·DSF 태그도 읽으며 세부 컨테이너 구조는 별도로 다룹니다.

라이브러리 해석값은 TagLib 스트림을 출처로 표시하고 원본 위치를 만들어 붙이지 않습니다.
손상된 파일을 라이브러리가 해석하지 못해도 이미 읽은 원본 관측값은 유지합니다. 메타데이터
추출 성공이 모든 오디오 프레임의 디코딩 성공을 뜻하지 않습니다. Ogg 헤더·이어지는 패킷의
범위를 검사하지만 전체 페이지 CRC와 코덱 프레임 검증은 이 단계에서 하지 않습니다.
읽기·출력 예산과 TagLib 호출 전 16 MiB 작업 예산을 적용하며, 내부 할당과 협력적 시간 제한의
강제 경계는 이후 격리된 스캔 작업자가 제공해야 합니다.

## 영상 컨테이너

media.structure 파서는 MP4·MOV 박스를 64비트 크기와 영상 조각까지 탐색하고, 영상·트랙
시간 기준, 표시 행렬·크기, 언어·핸들러, 샘플 기술 정보·수·표, 청크 위치와 모르는
메타데이터 박스를 보존합니다. ftyp 없는 QuickTime도 지원합니다. mdat 영상 데이터
전체를 메타데이터로 복사하지 않으며 외부 데이터 참조를 열지 않습니다.

Matroska·WebM은 EBML, 세그먼트·트랙 식별자, 시각·코덱, 영상·오디오 속성, 언어·색,
챕터·태그·첨부 데이터를 읽습니다. 크기 미상의 스트리밍 세그먼트·클러스터는 알려진
형제 구조 경계에서 멈춥니다. 모르는 메타데이터는 남기고 큰 인코딩 블록은 건너뜁니다.
AVI는 기본·스트림 헤더, 형식, INFO, OpenDML 프레임 수와 인덱스 크기를 읽고 영상 목록은
복사하지 않습니다.

MPEG 기본·프로그램 스트림에서 영상 크기·재생률, 팩·시스템 헤더, 스트림 ID와 사용자
데이터를 읽습니다. 전송 스트림은 188·192·204바이트 패킷, 여러 패킷의 PAT·PMT 조립,
CRC, 프로그램·기본 스트림 PID와 기술자 원문을 지원합니다. 연속성 누락·암호화된 데이터·
불완전한 PSI·마지막 잘린 패킷은 명시합니다. 선언된 컨테이너 구조를 검사하는 기능이며
모든 코덱 프레임의 정상 여부나 전체 재생 타임라인을 보증하지 않습니다. 원본 영역과
조립된 패킷의 출처를 구분하며 깊이·읽기·출력 예산을 적용합니다.

## 영상 세부 정보와 삽입된 그림

media.details 기능은 샘플 기술 정보, AVC·HEVC·AV1 파라미터 패킷, MPEG-4 기술자,
색·ICC·픽셀 비율, 편집 목록, 챕터 시각·트랙 연결, QuickTime 키·형식별 메타데이터,
커버 데이터, 자막 설정, Matroska 블록 시각, AVI 형식과 전송 스트림 언어·자막·등록 정보를
추출합니다. ID3 CHAP·CTOC·APIC와 FLAC 그림은 원본 영역을 보존하고, TagLib 복합 속성은
그림 바이트·속성을 라이브러리 출처로 별도 반환합니다. 첨부물이나 링크된 그림을 디스크나
네트워크에서 열지 않습니다.

FourCC는 원본 인코딩된 텍스트로 남기며, 내부 경로는 비ASCII·제어 바이트를 복원 가능한
표현으로 바꿔 Rust 경계가 실패하지 않게 합니다. 삽입 자료는 이 단계에서 크기가 제한된
바이트 관측값이며, 가상 하위 증거와 GUI 미리보기는 이후 구현합니다. 코덱 설정은 선언된
데이터이므로 디코딩 성공을 뜻하지 않습니다. 확장 QuickTime 오디오 구조와 여러 프레임이
묶인 Matroska 블록의 프레임 경계는 추측하지 않고 미해석 상태로 네이티브 디먹서에 맡깁니다.

## 프로세스 내부 미디어 검사와 디코딩

media.inspect·media.decode는 FFmpeg 9.0.2 공유 라이브러리와 Rust 입력 콜백을 사용합니다.
실행 프로그램, 네트워크, 프로토콜, 인코더, GPL·nonfree 구성과 시스템 의존성 자동 선택을
비활성화하고 외부 자원 열기를 차단합니다.

검사는 컨테이너·트랙 식별자, 시간·속도·언어·태그·색상, 코덱 설정, 프로그램, 챕터와
첨부 이미지를 추출합니다. 라이브러리 값에는 해당 트랙·챕터·프로그램을 기록하고 원본
위치를 만들어 붙이지 않습니다. 원본 위치를 보존하는 media.structure·media.details
관측값도 별도로 유지합니다.

지원하는 음성·영상 트랙별 한 프레임을 디코딩합니다. 음성은 샘플·형식·채널을 반환하고,
영상은 긴 변이 최대 256픽셀인 RGB24 미리보기로 제공합니다. 모든 프레임의 정상 동작을
보증하는 기능은 아닙니다. 일반 AVC·HEVC·MPEG·VP8·VP9·JPEG·PNG·원시 영상,
MP3·AAC·AC3·FLAC·Vorbis·Opus·ALAC·APE·WavPack·PCM 디코더를 활성화합니다.
코덱·프로필에 따라 지원하지 못할 수 있고, 소프트웨어 백엔드가 없는 AV1 디코딩도
지원 불가로 명시합니다. 미지원 코덱의 검사 결과와 이유는 보존합니다.

읽기·패킷 순회·프레임 버퍼·미리보기 복사·출력을 제한하며 작업 메모리 32 MiB를 먼저
반영하고 FFmpeg 단일 할당을 64 MiB로 제한합니다. 모든 내부 할당을 정확히 측정하거나
시간을 강제로 제한하지는 않으며, 해당 경계는 이후 스캐너 격리에서 보강합니다.

## PDF 메타데이터와 개정 이력

pdf.metadata는 검토한 qpdf 12.4.2와 libjpeg-turbo 3.1.4.1을 정적으로 연결합니다. 읽기 전용
Rust 입력으로 파싱하며 qpdf 실행 프로그램이나 외부 자원을 사용하지 않습니다. 문서 정보의
문자열·해석 전 바이트·사용자 정의 필드, 카탈로그 속성, XMP, 상속된 페이지 크기, 유니코드
첨부파일명, 스트림 속성·연결 관계와 디코딩한 첨부 데이터를 보존합니다.

제한된 토큰 판독기가 실제 마지막 startxref, 교차참조 테이블·스트림, 혼합 보충 구조와 Prev
연결을 따라 개정 이력을 읽습니다. 원본 사전·행 바이트와 위치도 보존합니다. 스트림 내부의
EOF 같은 문구는 개정으로 세지 않습니다. 삭제된 객체가 이전 매핑으로 다시 살아나지 않으며
압축 교차참조·객체 스트림도 지원합니다. 라이브러리 값은 객체를 식별하고 원본 위치를
만들어 붙이지 않습니다. 원본 교차참조 스트림 길이가 간접 참조이면 라이브러리 해석이
필요하다고 명시하고, 메타데이터 추출은 qpdf의 해석기를 계속 사용합니다.

미지원 필터, 잘못된 트리나 자원 제한에 걸려도 이전 관측값은 보존하고 미완료 원인을
반환합니다. 빈 암호로 열 수 있는 암호화 문서는 읽지만 보호된 문서는 password_required와
부분 결과를 반환합니다. 사용자 암호 입력 기능은 아직 공개하지 않았습니다.

작업 메모리 32 MiB와 읽기·순회·출력 한도를 적용하고 qpdf 내부 Pl_Buffer가 커지기 전에
파서별 제한을 확인합니다. 객체 스트림 압축 해제도 이 검사를 거칩니다. 모든 내부 할당의
정확한 측정이나 강제 실행 격리까지 제공하는 것은 아닙니다.

## PDF 보안 구조

pdf.security는 pdf.metadata의 결과와 현재 교차참조 객체 전체를 조사합니다. 연결되지 않은
사전과 압축 객체도 포함합니다. 직접 사전·배열에는 깊이·항목 제한을 적용하고 간접 참조는
식별자를 보존한 뒤 객체 테이블에서 한 번씩 조사합니다. 페이지 부모나 동작 참조의 순환이
무한 탐색으로 이어지지 않습니다. 모르는 키·문자열·문자열 바이트, 필터, 객체 스트림 식별자와
원본 객체 위치를 남깁니다. 과거에 교체되거나 삭제된 객체를 완전히 복원하지는 않습니다.

암호가 필요한 문서도 원본 암호화 사전과 암호 필터 설정을 보존합니다. 빈 암호로 열 수 있는
RC4·AES 문서는 라이브러리가 해석한 암호 방식과 권한도 제공합니다. 암호나 파생 암호화 키는
출력하지 않습니다. 사용자 암호 입력 기능은 이후 작업입니다.

서명 사전·인증서·서명 바이트·서명자 주장과 ByteRange를 보존합니다. 정수 개수, 순서, 파일
경계, 마지막 포함 위치, 서명되지 않은 뒷부분 크기와 두 범위 사이의 제외 영역이 Contents의
16진 문자열의 원본 위치·바이트와 일치하는지 확인합니다. 압축 객체나 간접 참조 Contents의
원본 위치 검사는 불가로 표시합니다. 이는 구조 정보입니다. cryptographic_verification은
항상 not_performed이며 CMS 해시·인증서 신뢰·폐기 상태·서명자 진위는 검증하지 않습니다.

개정 정보는 EOF 문구 개수가 아니라 실제 교차참조 연결에서 얻습니다. 선형화 PDF의 앞으로
향하는 Prev 참조도 보존합니다. 증분 개수는 앞으로 향하는 교차참조 연결을 뺀 구조상 개수이며
전체 과거 개정 복원이나 선형화 검증을 뜻하지 않습니다. 마지막 EOF 뒤의 공백 아닌 데이터도
별도로 표시합니다.

JavaScript 문자열·스트림, 실행·URL·원격 동작, OpenAction·AA, XFA·RichMedia·첨부 표시를
관측 정보로 남깁니다. 선택한 JavaScript 스트림만 디코딩하고 외부 스트림은 거부합니다.
동작·스크립트는 실행하지 않고 URL·파일명도 열지 않습니다. C++는 관측한 구조를 반환하며
심각도와 조사 정책은 Rust가 담당합니다.
